# repo-ai 0.8.0rc1 release notes (release candidate, not released)

**Status:** a private release candidate.
- **Not published** to any package registry; not tagged.
- **Qualified scope:** core `verify` has Session A's verdict CONDITIONAL_WITH_EXPLICIT_LIMITATIONS on main `903984a` (PR #24, comment 6414777596). This candidate differs from `903984a` in the ways listed in [RC1.md](RC1.md), and has a separate read-only source and wheel review recorded there. The prior candidate failed a required macOS test because the system Python launcher could not access Xcode inside the sandbox. The corrected interpreter resolver passed independent review and targeted CI; full CI of the new candidate remains outstanding. The earlier qualification is not an exact-build CI result.
- **ProofLab did not qualify** and is not part of this release's supported capabilities.

## Install

repo-ai is not on PyPI. Install the wheel you built or were given, and check its sha256 against [RC1.md](RC1.md):

```sh
shasum -a 256 repo_ai-0.8.0rc1-py3-none-any.whl
pipx install ./repo_ai-0.8.0rc1-py3-none-any.whl     # or: python -m pip install ./repo_ai-...whl
repo-ai --version                                    # repo-ai 0.8.0rc1
```

- **Requirements:** Python ≥ 3.10.
- **Dependencies:** one runtime dependency, `pathspec` (plus `tomli` on Python 3.10).
- **Network:** pipx downloads them from PyPI, unless you point it at local copies (`--pip-args="--no-index --find-links DIR"`). Nothing else on the path below uses the network.
- **To remove it:** `repo-ai uninstall` in each repository, then `pipx uninstall repo-ai`.

## Five minutes: did my change break something, and is the evidence still current?

A repository with a `pytest` suite and declared pytest configuration (for example
`[tool.pytest.ini_options]` in `pyproject.toml`), and a change you are about to commit.
Otherwise pass `--test-command "python -m pytest"` to verification:

```sh
cd your-project
repo-ai init --agent claude          # or --agent none: no CLAUDE.md, skills or hooks
# ... edit a function ...
```

1. **Understand the change.**
   ```sh
   repo-ai impact --changed
   ```
   What the diff touches: changed units, importers, linked tests.
2. **Identify the tests.**
   ```sh
   repo-ai verify
   ```
   This is read-only. It names the test files that can show a regression, with the evidence for each link and a confidence. When nothing is linked to a behavioural change, the plan abstains. If execution
   requires and successfully runs the full suite, it can report a full-suite pass
   despite no selected tests. This establishes only that the existing suite passed.
   Without a required full suite, no linked tests means NOT VERIFIED.
3. **Run isolated verification.**
   ```sh
   repo-ai verify --run
   ```
   - The selected tests run in a disposable copy of the working tree, never in it, inside a sandbox: seatbelt on macOS, bubblewrap on Linux, or a container with `--sandbox podman|docker`.
   - The source tree is checked before and after.
4. **Inspect the baseline comparison.** A failing test is compared with the same test on the base commit. The verdict says which kind of failure it is:
   - `regression`: a new failure the change caused;
   - `failing (all failures pre-existing at the base)`: the base fails the same way;
   - `NOT VERIFIED`: nothing could show it.
5. **Check evidence freshness.**
   ```sh
   repo-ai evidence
   ```
   - **Exit codes:** 0 current, 2 stale, 1 none.
   - **What makes it stale:** the evidence covers only the exact working tree and test environment it ran on. Any edit, a new commit on the base, or a changed interpreter, site-packages or `node_modules` makes it stale.
   - **The gate:** with `verify_gate = true`, the optional Stop-hook gate, Claude Code is told when its change has no current passing evidence.
6. **Review.**
   ```sh
   repo-ai review
   ```
   A change passport for the pull request: what the diff touches, the tests, the risks, the blind spots. It is evidence, not an approval.

A passing verdict covers only the tests that ran. It is never proof that the change is correct.

|---|---|---|

| `init`, `status`, `privacy`, `doctor`, `uninstall` | Claude Code wiring (hooks and skills) or none; `uninstall` removes managed stores and wiring; user exports and edited files are retained and listed | the wheel journey checks |

**Test runners:**
- **Supported:** `pytest`, `node --test` (held-out-7).
- **Work, but not qualified:** `unittest`, and TypeScript under node's type stripping. They are covered by tests and CI but have no held-out evaluation, so they are not claimed (Session A's B2).
- **Not supported:** Jest, Vitest, Mocha and other opaque runners, which run only as a whole suite; monorepos with several runners.

## Experimental, opt-in, not part of the supported claims

- **`repo-ai prove` (ProofLab).**
  - **Not qualified, not certified;** excluded from this release's capabilities.
  - **Three false proofs are known and open:** `always-equal-class`, `swallowed-assertion` and `importorskip-zero-entry-points` (issue #59). Every passport, report, status, in-toto export and evidence record names them.
  - **Scope:** node claims are never supported.
  - **Where it is wired in:** no hook or gate calls it. Its skill, `/repo-prove`, runs only when you ask.
- **Capability discovery** (`capabilities recommend / candidates / select`), **third-party skills** (discover, install, trials), **plugin inspection**, **self-improvement** (`--smart`, `learn`, `optimize`), **`--feature-set full`**.
- **verify:** adaptive run shapes, caches and evidence reuse; the zero-configuration test command; `--image`; the Stop-hook gate's effect on agents.

**Not in this release:** the retrieval prototype (PR #57, draft), the evidence graph (PR #52, draft), Mission Control.

## Privacy and security boundaries

- **No code runs without `--run`.** repo-ai runs repository code only on `verify --run` / `--record` (and the experimental `prove run`), always in the sandbox. It never executes an interpreter inside the repository on the host, nor a version-manager shim the repository's version file steers.
- **On disk:**
  - Everything repo-ai keeps is under `.repo-ai/` in the repository (machine-local stores are gitignored). `repo-ai privacy` lists every store, what it holds and whether it is committed.
  - Outside the repository: an optional per-user configuration (`~/.config/repo-ai/`); the opt-in registry and capability approvals (`~/.local/share/repo-ai`); an empty, private workspace folder in `$TMPDIR` after `verify --run`.
- **No network on the path above.** The commands that use it are listed in the README (`--online` skill commands, `sandbox pull`, `prove report --publish-pr`).
- **`doctor --agent claude`** runs `claude --version`. That is Claude Code, which keeps its own files and may send its own telemetry.
- **`init --agent claude`** writes:
  - `CLAUDE.md`'s managed block;
  - skills;
  - four hooks (SessionStart, UserPromptSubmit, PostToolUse, Stop), which fail open.

  It grants no permissions or allow rules.
- **Local forgery:** evidence and passports are local files; anyone who can write `.repo-ai/state` can forge one.

## Performance (no speed claim)

- **`verify --run` can be slower than running the native suite on small suites.** In held-out-7 it was 1.44×, 2.31× and 1.70× the native time on three projects, and faster only on the two larger ones.
- **Planning, the copy and the integrity check** cost about 0.6–1 s per run.
- **A hanging node test settles in about 36 s,** not 15 s. Python's settles in about 7 s.
- **Cancellation was clean** on the projects measured, but was not measured on every one.

## Known issues

- **A miss on a fresh project:** a verdict of `not verified: no test is linked` (exit 1; the gate blocks) is a miss, not a false pass.
- **Flaky tests:** a deliberately flaky test gave `regression` in 1 of 3 runs on two projects. The two passing verdict forms can alternate.
- **NUL bytes:** `verify --gate` is silent on a `.py` change that contains NUL bytes, because the file is treated as binary.
- **Custom `out_dir`:** in that layout `init` writes no `.gitignore` entry for the index, so a committed `index.db-shm` makes a run refuse ("working tree changed"). It fails closed.
- **The environment identity** does not see `__pycache__` in site-packages, packages linked into site-packages, or editable installs outside the repository.
- **`context` on prose:** natural-language queries find their files less well (holdout recall@5 0.320) than exact names do. A symbol named like a common word (`mean`, `get`) is found from the name alone, not from `mean()` or backticks inside a sentence.
- **`review` and `verify` evidence:** `review` does not yet read `verify` evidence, so it can say "no recorded test run" right after a passing `verify --run`.
- **ProofLab:** see Experimental.

## Migrating from 0.7.7

- **Install** the new wheel over the old one with `pipx install --force ./repo_ai-0.8.0rc1-py3-none-any.whl` (or `pip install`): 0.8.0rc1 is newer than 0.7.7, and the `v0.7.7` tag is untouched.
- **Re-run `repo-ai init --agent claude`** (or your agent choice) in each repository. That refreshes the managed CLAUDE.md block, skills and hooks; the experimental skills now say they are experimental.
- **The index** (schema 6) is unchanged; `repo-ai update` refreshes it.
- **Evidence and passports from untagged development builds reporting 0.7.7**
  read as **stale** under 0.8.0rc1. Evidence with missing version/environment identity
  also requires a rerun. The actual `v0.7.7` tag has no `verify` or `evidence` command.
  Run `repo-ai verify --run` again; no data needs converting.
- **New configuration keys** are all off or empty by default: `verify_gate`, `verify_gate_mode`, `verify_gate_max_blocks`, `verify_test_command`.
- **`repo-ai uninstall`** now also removes ProofLab's store and every verify record. It keeps what it does not recognise.
