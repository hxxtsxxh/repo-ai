## The fixes

| Low | Before | After | Residual |
|---|---|---|---|
| L2 | The Linux probe resolved each exposed path, checked it for sockets, then passed the path to bubblewrap, which resolved it again. A symlink swapped into the path in between changed what was bound. | With bubblewrap 0.10 or later: `_pin` opens the resolved path one component at a time with `O_NOFOLLOW` (`O_PATH` on Linux); a symlinked component means the path is not bound. The socket walk starts from that descriptor (a subdirectory whose device and inode changed since it was listed counts as a socket), and bubblewrap binds the descriptor (`--ro-bind-fd`, passed with `pass_fds`). The descriptors live as long as the prefix (`_PinnedPrefix`). | Older bubblewrap (no `--ro-bind-fd`; Ubuntu 24.04 ships 0.9, Debian 12 0.8, Ubuntu 22.04 0.6): path binds as in 0.11.9, race open. A process of the same user can still create files, sockets included, inside a bound directory after the check. `_execution_sandbox_prefix` (live runs) still binds install roots by path (queued). |
| L4 | A licence-named file below the root never got `overlong-code-line`, so a one-line minified script named `vendor/LICENSE` lost that finding (its content was still scanned in windows). | The finding is skipped only when the long line reads as prose (`_prose_line`: under 1% code punctuation, and either at least 8% spaces with a mean word length of at most 15, or at least half letters from scripts written without spaces). | A heuristic: prose-like padding around code avoids the overlong finding, but not the windowed behaviour rules. |
| L6 (rest) | `git ls-files --others --exclude-standard` read `.gitignore` files in the agent's workspace, so an agent-written ignore file could hide its new files from the untracked count. | The base commit's `.gitignore` files (regular files only) are read from the pre-run copy of `.git` (`git cat-file --batch`), anchored to their directories with glob characters escaped, trailing spaces and empty negations handled, root first then deeper, after `info/exclude`. A nested repository is expanded file by file. Names are NUL-separated and decoded with `os.fsdecode`. | Metric only, as before: grading always used a copy. New files under paths the base already ignores are not counted. |

## First review (PR #99, independent agent) and what changed

The first version bound `/proc/<pid>/fd/<n>` by path. CI's `sandbox-bwrap` job showed bubblewrap cannot open that
from inside its namespaces ("Can't find source path /proc/…/fd/14: Permission denied"), so every program bound back
from a hidden directory failed to probe; with a bubblewrap that resolves the source first it would only have
narrowed the race. The module also no longer imported on Windows (`os.O_DIRECTORY`). Both fixed as above, with a
real-bubblewrap test that the program runs and that no descriptor to the bound directory reaches it. The review's
gitignore mismatches (sibling order, a lone `!`, glob characters in directory names, trailing spaces, symlinked
ignore files), nested repositories, non-UTF-8 names and unwrapped CJK licence text are fixed with tests; on an
untouched base the count is compared with git's own.
