## The fixes

| Low | Before | After | Residual |
|---|---|---|---|
| L2 | The Linux probe resolved each exposed path, checked it for sockets, then passed the path to bubblewrap, which resolved it again. A symlink swapped into the path in between changed what was bound. | `_pin` opens the resolved path one component at a time with `O_NOFOLLOW` (`O_PATH` on Linux); a symlinked component means the path is not bound. The socket walk starts from that descriptor and bubblewrap binds `/proc/<pid>/fd/<n>`, so the bound directory is the checked one. The descriptors live as long as the prefix (`_PinnedPrefix`). | A process of the same user can still create files, sockets included, inside a bound directory after the check (as before). The sandboxed program cannot see the parent's `/proc` (it gets its own). |
| L4 | A licence-named file below the root never got `overlong-code-line`, so a one-line minified script named `vendor/LICENSE` lost that finding (its content was still scanned in windows). | The finding is skipped only when the long line reads as prose (`_prose_line`: at least 8% spaces, under 1% of the characters code punctuation, mean word length at most 15). | A heuristic: prose-like padding around code avoids the overlong finding, but not the windowed behaviour rules. |
| L6 (rest) | `git ls-files --others --exclude-standard` read `.gitignore` files in the agent's workspace, so an agent-written ignore file could hide its new files from the untracked count. | The base commit's `.gitignore` files are read from the pre-run copy of `.git` (`git cat-file`), anchored to their directories (`_anchored`) into one excludes file; the workspace's ignore files are not read. Names are NUL-separated. | Metric only, as before: grading always used a copy. |
