No provider is needed for indexing, context, impact, `verify` or `coverage`. Providers matter only for live
[missions](/repo-ai/docs/missions/), [tournaments](/repo-ai/docs/tournaments/) and
[handoffs](/repo-ai/docs/handoff/). This page records observations, not endorsements.

from repo-ai launching Claude as a mission provider, which is the blocked path above.
:::

## Checking providers locally

```sh
repo-ai agents list      # is an executable present? no subprocess, no model call
repo-ai agents doctor    # sandboxed --help/--version probes; no login check, no model call
repo-ai agents route     # what --agent auto would choose, with a status class
```

`agents route` reports a `status_class` such as `NOT_INSTALLED`, `NOT_AUTHORIZED`, `BLOCKED_AUTH`, `BLOCKED_QUOTA`,
`BLOCKED_SANDBOX`, `UNSUPPORTED` or `ISOLATED_READY`. There is no "host ready" state: repo-ai has no un-isolated
execution path. Routing does not check login or quota before a live run.

## Per-provider notes

### IBM Bob

Install and log in to Bob as its documentation describes. repo-ai passes your `--max-cost-usd` to Bob's own cost cap,
so a positive ceiling is enforced by the provider. Cost figures are provider-reported, not billing records.

### Codex CLI

Log in with Codex's own flow. repo-ai runs Codex with a scratch `HOME` seeded only with Codex's auth file, under
repo-ai's outer sandbox. Because nested sandboxes are not supported on macOS, repo-ai passes Codex's
`--dangerously-bypass-approvals-and-sandbox` **only after** confirming its outer sandbox is active for that run; if it
is not, the run is refused. The outer sandbox is then the only write boundary. Codex has no hard USD flag, so a
positive `--max-cost-usd` is refused and cost is recorded as `UNKNOWN`, never `0`. Bound runs with `--max-seconds`.

### Antigravity (`agy`, macOS only)

agy has no scratch-HOME login, so it runs with the real `HOME`, but the seatbelt profile denies reads under `HOME`
except its own state directory (minus history), `~/.gemini/config`, `~/.local` and the two keychain database files it
needs to authenticate. Those files are encrypted, but the agy process can read them and has network access. repo-ai
runs it headless with edits only, shell actions denied, and never with `--dangerously-skip-permissions`. If that
exposure is unacceptable to you, do not use `--agent agy`.

### Claude Code

Use it as a host (`repo-ai init --agent claude`, then `repo-ai doctor --agent claude`). Do not depend on it as a
mission provider.

### Gemini CLI

Not usable with the account that was tested. No further claim either way.

## What every live run shares

- Live calls happen only with `--run --allow-live-provider`.
- The task text and the workspace files the agent opens go to that provider, under that provider's terms.
- Network is allowed for the provider process (the model API needs it), so it can send what it can read.
- Subscription quota and unknown dollar cost are separate from any spending ceiling you set.

Details: [Security & privacy](/repo-ai/docs/security/#live-provider-runs).
