# Release Notes

Draft clear release notes and choose the right semantic version bump.

## Process

1. Group merged changes into Added / Changed / Fixed / Removed / Security.
2. Choose the bump: MAJOR for breaking changes, MINOR for features, PATCH for fixes.
3. Write user-facing notes, not commit dumps; link issues where useful.
4. Update `CHANGELOG.md` with the new section under the version and date.

## Example heading

```
## [1.4.0] - 2026-01-15
### Added
- Export to CSV from the reports page.
```

Keep notes honest: list breaking changes prominently.
